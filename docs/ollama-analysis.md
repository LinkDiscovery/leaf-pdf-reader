# Ollama 문장 패턴 연결 — 로컬 시험용

2026-11-16. `experiment/sentence-pattern-ollama` 브랜치. **연결 기능과 모델의 분석 품질은 별개다. 현재 모델의 자동 분석은 품질 검사를 통과하지 못했으며 운영 사이트에는 배포하지 않는다.**

## 현재 구성

리더 → 이 PC의 Leaf 연결 프로그램(127.0.0.1:4175) → Ollama(127.0.0.1:11434) → 패턴·뜻 초안 → 사용자 검토·수정 → 메모에 넣기 → 저장.

PDF는 전송하지 않는다. 분석 버튼을 누른 문장 하나만 Ollama에 전달한다. 앱을 열거나 문장 편집창을 열기만 해서는 모델을 호출하지 않는다. 모델 파일은 Ollama가 기기에 보관하며 Firebase 용량을 쓰지 않는다. 로그인 상태에서 **저장한** 문장과 메모는 기존 Firebase 규칙으로 동기화된다. 연결 주소는 해당 브라우저에만 저장한다.

현재 데스크톱에는 Ollama 0.40.16이 이미 설치되어 있었다. 기존 `qwen3:8b`, `llama3.1:8b`는 유지했고, `qwen3.5:9b`(약 6.6GB)를 추가했다. Ollama의 전역 설정·시작 프로그램·방화벽은 변경하지 않았다.

## 실행 순서

Node.js 24 이상을 사용한다. Ollama를 먼저 실행한다.

1. 다른 컴퓨터라면 `ollama pull qwen3.5:9b`로 모델을 받는다. 현재 PC에는 다운로드를 마쳤다.
2. 저장소의 **Ollama-Analysis.cmd**를 연다. CPU 모드의 연결 프로그램이 실행되며 창을 닫으면 연결도 끝난다.
3. `npm run build` 후 **PDF-Reader.cmd**로 로컬 리더를 연다. 주소는 `http://127.0.0.1:4173`이다. 이번 실험 기능은 GitHub Pages 운영 주소에는 없다.
4. **나의 문장 → 패턴 분석 → Ollama 연결 설정 → 연결 확인**을 누른다. 기본 주소는 `http://127.0.0.1:4175`이다.
5. **분석 시작**을 누르고 결과를 검토한다. 틀린 부분을 고친 뒤 **메모에 넣기 → 저장**한다. 분석 자체는 기록을 자동 저장하지 않는다.

브라우저에서 로컬 네트워크 접근을 요청하면 이 연결에 대해 허용해야 한다. 분석 취소, 원문 변경, 편집창 닫기는 요청을 취소한다. 연결 프로그램이 꺼져 있거나 모델이 없으면 안내하며, 원문·기존 메모는 보존한다. CPU 모드는 느릴 수 있고 요청은 최대 약 3분 후 중단한다.

현재 실행기는 GPU 문제를 피하기 위해 CPU 모드로 고정했다. GPU 복구 후 별도 시험할 때만 `node scripts/ollama-bridge.mjs`로 자동 모드를 사용할 수 있다. `LEAF_OLLAMA_MODEL` 환경변수로 연결 프로그램의 모델을 바꿀 수 있지만, 다른 모델의 정확도·속도는 검증되지 않았다.

## 실제 모델 시험

기기: Ryzen 7 3700X / RAM 64GB / RTX 2070 SUPER 8GB / NVIDIA 드라이버 551.78. 수치는 이 PC와 이 문장들에서 관찰한 값이며 다른 기기의 속도 보장이 아니다.

- 기존 Qwen3 8B의 빠른 모드: 20문장 실행, 첫 요청 약 7.5초, 이후 대략 0.3~0.7초. `suggest that`를 원인으로 해석하거나 `too ... to` 틀을 잘못 만드는 등 오류가 있었다.
- Qwen3 8B 추론 모드: 토큰 한도 초과와 CUDA 오류 발생. 이후 `nvidia-smi`가 **GPU is lost. Reboot the system to recover this GPU**를 출력했다. GPU 장애의 원인을 확정하지 않았으며 재부팅이나 드라이버 변경은 수행하지 않았다.
- Qwen3.5 9B는 CPU에 정상 적재됐다. 짧은 5문장 비교와 별도 8문장을 실행했고, 짧은 응답은 대략 10~21초였다. 원하는 `It remains + 형용사 + for A + to B`가 나오는 경우도 있지만, 가정법의 `might have been`을 생략하거나 원문에 없는 가주어 구조를 만들어 내는 오류가 남았다.
- Qwen3.5 9B CPU 추론 모드에서 조건문 한 문장은 180초 내 답을 완성하지 못해 취소됐다.

**결정:** 서버 연결을 구현한 것만으로 문법 분석이 검증된 것은 아니다. 현재 결과를 학습용 정답으로 제공하지 않는다. 노트북으로 이전하는 단계는 좋은 모델·설정을 찾고 GPU 실행 안정성을 확인한 뒤 진행한다. 같은 모델을 노트북으로 옮기는 것만으로 정확도가 개선되지 않는다.

## 검증과 재현

빌드, UI 22개 검사, 연결 서버 3개 검사, Firebase 에뮬레이터 3개 검사를 통과했다. 실제 앱에서도 Ollama CPU 분석 → 메모에 넣기 → 기존 메모 보존 → 저장 → 새로고침 복원을 확인했다. 모델의 문법 정확도 승인을 뜻하지 않는다.

- `npm run build`: 타입 검사 및 빌드.
- `npm test`: PDF·단어장·음성·패턴 편집·취소·백업 UI 검사. AI 응답은 모의 처리한다.
- `node --test scripts/test-ollama-bridge.mjs`: 허용 Origin, 입력 크기, 다른 API 접근 차단, 취소 전달, 동시 요청 제한 검사.
- `node scripts/probe-ollama.mjs qwen3.5:9b held-out --cpu --plain`: 실제 모델 시험. `--thinking`, `--quick`, `--one=19` 등의 비교 옵션을 제공한다. 결과는 `.cache/ollama-evaluations/*.json`에 지시문과 원문·응답·시간을 기록한다. 시험 문장만 사용하며 운영 사용자 데이터를 수집하지 않는다.

연결 프로그램은 루프백에만 바인딩한다. 허용된 앱 Origin과 작업 전용 요청만 받고, Ollama의 다운로드·관리 API를 일반 프록시로 공개하지 않는다. 미래 노트북에서 다른 기기로 제공하려면 HTTPS·인증·접속 구성을 별도로 추가해야 한다. 현재 코드의 바인딩을 외부 공개 주소로 바꾸는 것으로 배포를 끝내서는 안 된다.
